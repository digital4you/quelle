# Quotation-page and Nuxt speed optimization

Both targeted paths are faster in three paired before/after rounds, with identical
extracted text in every pair. The new full 25-query run still favors Quelle
overall, but Firecrawl retains an end-to-end advantage on the quotation pages
and a small advantage on the original Nuxt fallback URL in a separate repeat.
These are improvements, not evidence that every remaining speed gap is closed.

## Changes

- **Nuxt:** literal template examples inside `pre`, `code`, `samp` and `kbd`
  no longer count as unfinished application markup. Actual placeholders,
  including ones split across inline elements, and real framework bindings
  still require rendering. The HTML fallback now extracts the complete
  server-rendered article without an unnecessary browser launch. Its negotiation
  retry, error classification and public-address checks remain in place.
- **Synchronous pages:** the browser observes timer and asynchronous API activity
  from document startup. A fully loaded page with no pending timers or observed
  asynchronous network work can finish after 80 ms of content stability.
  Pending timers, asynchronous network activity, modules and async scripts keep
  the existing 350 ms window. Failed observation also keeps that window.
  Populated-content/table checks, the seven-second default maximum and final
  document validation still apply. The observer returns native API results
  unchanged and does not read fetch bodies or attach promise handlers.

Implementation: [template detection and renderer launch](../../src/pages.rs),
[activity observer](../../src/pages/readiness-init.js),
[readiness check](../../src/pages/readiness.js).

## Paired old/new comparison

The preserved previous release and the new release read the exact old candidate
URLs for `hard04` and `tech05`, including the original unversioned Nuxt URL.
Each arm started a fresh process in each of three rounds. Arm order alternated;
both used `/api/content` with supplied URLs and a five-document limit. These
timings exclude discovery and are separate from the full pipeline comparison.
No Brave calls were made for this experiment.

| Target | Before, median | After, median | Reduction |
| --- | ---: | ---: | ---: |
| JavaScript quotations | 1.705 s | **1.438 s** | 16% |
| Original Nuxt fallback | 4.682 s | **3.272 s** | 30% |

| Round | Quotations before / after | Nuxt before / after |
| --- | ---: | ---: |
| 1 | 1.872 / 1.438 s | 4.779 / 3.533 s |
| 2 | 1.705 / 1.433 s | 4.282 / 3.272 s |
| 3 | 1.695 / 1.459 s | 4.682 / 3.215 s |

All six query pairs improved. Each returned two quotation sources and five Nuxt
sources, with zero errors. All **21 corresponding source-text comparisons were
byte-for-byte identical**. This establishes no extracted-text loss for these
tested URLs, rather than inferring quality from matching keywords.

Quotation render stages dropped from approximately 0.97–0.99 s to 0.71–0.74 s.
The new Nuxt path made zero browser launches in all three rounds; it returned
the same 34,855-character article from the HTML response. Evidence:
[summary](results/2026-11-27-speed-ablation/summary.json),
[binary hashes and controls](results/2026-11-27-speed-ablation/manifest.json).
Individual responses and per-arm logs are retained alongside those files.

## Full 25-query benchmark

The full run completed on November 27, 2026, from 17:20:00 to 17:23:16 CET.
It used the unchanged 25 queries and the same supplied Brave key. One live
Brave response per query was shared identically between Quelle and SearXNG.
All 25 live requests and all 50 paired replay requests succeeded; a separate
replay smoke check also succeeded. Candidate URL sets matched for all 25 pairs.

Controls match the [previous quality-fix run](QUALITY-2026-11-27.md): CH,
explicit query language, strict SafeSearch, spellcheck off, five candidates,
engine order, no follow-up search and no reranker. Quelle used Lightpanda and
`/api/content`; SearXNG used `braveapi` followed by self-hosted Firecrawl
`/v2/scrape`, Markdown, `onlyMainContent: true`, and available Playwright.
Both allowed four concurrent page fetches. Query order was seeded, pipeline
order alternated, and pipelines ran sequentially. Services started fresh;
normal in-run caches remained enabled. Image identities and fetch budgets
match the previous run. No compilers ran alongside the measured pipeline calls.

## Remaining speed gaps and selected repeats

The four full-run losses were quotations (1.458 versus 1.347 s), MDN (2.011
versus 1.880 s), Zefix (1.401 versus 1.364 s), and Fedlex (7.551 versus 1.588 s).
Fedlex's speed comparison is not equivalent useful retrieval: Quelle returns
legal text while Firecrawl returns JavaScript-required notices.

Six cases were repeated in fresh services with no new Brave requests. The two
targets used their old failing snapshots; the other four used the new full-run
snapshots. [Snapshot provenance](results/2026-11-27-speed-diagnostic-input/snapshot-origins.json)
records that distinction. These selected repeats are not pooled into the main
25-query results.

| Repeat | Quelle | SearXNG + Firecrawl | Observation |
| --- | ---: | ---: | --- |
| Quotations, old page set | 2.046 s | **1.312 s** | The browser still finishes in 0.715–0.727 s, but total request latency varies. |
| Original Nuxt fallback | 3.340 s | **3.170 s** | Complete article, zero browser launches; a 0.170 s gap remains. |
| MDN 429 | **1.827 s** | 1.915 s | The small full-run loss reverses. |
| Zefix/UID | **1.378 s** | 1.544 s | The small full-run loss reverses; both still fail on online-services. |
| Redis | **2.216 s** | 5.196 s | The full persistence article remains present. |
| Fedlex | 7.185 s | **1.836 s** | Quelle retains legal text in all four outputs; Firecrawl returns notices. |

The shorter quotation render is repeatable, but it does not eliminate the
initial HTTP fetch before the browser fetches the page again. Likewise, Nuxt
still pays for the failed Markdown negotiation and HTML retry. No universal
latency win or confidence interval is claimed from these few live-origin runs.
Evidence: [repeat results](results/2026-11-27-speed-check/case-summary.json)
and [renderer log](results/2026-11-27-speed-check/quelle.log).

## Quality and verification

The new Rust regressions and browser fixtures were authored before production
changes. The original implementation reproduced the Nuxt false positive and
failed the two synchronous-page speed checks. The final implementation passes
all **37 Rust tests**, **nine browser checks**, Clippy with warnings denied,
targeted formatting and diff checks. Release compilation and artifact accounting
also pass. Browser checks cover synchronous document writes, cleared timers,
pending timers with callback arguments, delayed fetch bodies, XHR callbacks,
background requests, delayed application content, delayed tables and hidden
placeholders. See [before](results/2026-11-27-speed-ablation/readiness-before.json)
and [after](results/2026-11-27-speed-ablation/readiness-after.json).

The full-run content audit confirms the earlier fixes: the VAT rate table and
PostgreSQL table retain structure; `#a773` and `#DATATYPE-NUMERIC-TABLE` survive;
Rust code retains indentation; SNB still has 94 characters before its heading;
Redis retains the 13,009-character article; all four Fedlex outputs contain
legal text with no loading-screen output. The frozen Nuxt repeat retains the
complete article and its code while avoiding rendering.

This is a development-set retrieval benchmark and an assistant audit, not
independent blinded grading, a load test or an answer-generation evaluation.
Live origins and search candidates vary. Larger-pool refill and optional
reranking remain outside the unchanged five-candidate controls. Existing
coverage limitations and the 150-page PDF cap are not addressed by these
latency changes.

Task-owned benchmark containers, volumes and processes were removed. Existing
services were not restarted. Raw artifacts are ignored by Git; implementation,
tests, runners, queries and reports are versionable.
