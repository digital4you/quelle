# Quality fixes and the final 25-query comparison

The reported Nuxt retrieval, citation-anchor, table-structure, SNB cleanup and
Fedlex loading-screen defects are fixed in the tested cases. Redis no longer
waits for unrelated network activity. Quelle is faster on 23 of 25 query pairs
in the new full run. A separate repeat against the old failing URLs confirms the
Nuxt recovery and Redis improvement, while exposing the additional cost of the
Nuxt fallback.

## What changed and what was verified

| Issue | Change | Observed result |
| --- | --- | --- |
| Missing Nuxt article | Retry the original HTML URL once when content negotiation produces a missing Markdown variant or HTTP 406. Keep explicit Markdown failures and ordinary HTML 404s as errors. | The original unversioned URL now returns the Nuxt 4 article, 34,855 characters, with no error in the frozen repeat. |
| Lost section links | Preserve validated fragments in evidence links and extracted link lists. Normalize them away only for fetching and crawl scheduling. | KMU's `#a773` and PostgreSQL's `#DATATYPE-NUMERIC-TABLE` survive. Private/unsupported link targets remain rejected. |
| Flattened tables | Share the Markdown table formatter with content extraction; retain captions, expand bounded row/column spans, escape cell pipes and separate block text within cells. | ESTV's old/new date columns and all three VAT rows survive as explicit table rows. PostgreSQL and Swisscom tables retain structure; Rust code indentation still survives. |
| SNB navigation and consent noise | Prefer a substantial main/article region, share chrome/consent filtering, and supplement contact targets outside the article. | Text before the SNB heading falls from 1,146 to 94 characters; Firecrawl has 96. Quelle returns 4,807 characters versus Firecrawl's 7,033, retaining the dated decision and PDF link. |
| Intermittent Fedlex loading screen | Reject empty main regions and recognized application-loading messages despite lengthy support/footer text. Browser readiness checks populated main content and tables, then waits for 350 ms of content stability. | All four retained Fedlex sources contain legal text in the full run and the separate repeat. No retained source contains the previous loading screen. |
| Redis render delay | Start content-readiness checks at DOMContentLoaded instead of waiting for network quiet. Keep the seven-second default maximum and post-render quality validation. | Redis query time falls from 8.029 s in the previous rematch to 3.155 s in the new full run and 1.969 s in the repeat, with the article intact. |

Redis's renderer itself took 7,004 ms in the previous rematch, 2,055 ms in the
new full run, and 956 ms in the repeat. Its retained article has 13,009 characters
and includes the RDB/AOF persistence explanation. Live network variability remains;
the improvement is not a claim that every request finishes in under a second.

## Main benchmark

The full run completed on November 27, 2026, from 16:46:59 to 16:50:24 CET.
It uses the same 25 queries, evidence criteria and supplied Brave key as the
[previous rematch](REMATCH-2026-11-27.md). Each query made one live Brave request;
both pipelines received that identical response through authenticated local
replay. All 25 live requests and all 50 paired replay requests succeeded, plus
one replay smoke check. The supplied candidate URL sets matched for all 25 pairs.

Controls remain CH, explicit language, strict SafeSearch, spellcheck off, five
candidates, engine order, no follow-up search and no reranker. Quelle used
`/api/content` with Lightpanda; SearXNG used `braveapi` followed by self-hosted
Firecrawl `/v2/scrape`, Markdown and `onlyMainContent: true`, with Playwright
available. Both allowed four concurrent fetches. Pipelines ran sequentially,
in alternating order, with the same seeded query order. Services were fresh at
run start; normal in-run caches remained enabled. Container image identities
match the previous run. The Firecrawl budget remained 25 seconds, and Quelle's
page-fetch budget remained 25 seconds, including its own fallback policies.

## Validation and limits

Five new Rust regression tests and the revised table expectations were authored
before implementation. All **35 Rust tests** pass, along with
`cargo clippy --locked --bin quelle -- -D warnings`, targeted formatting checks
and diff checks. Release compilation succeeded. Query/binary hashes, candidate
counts, duplicate/error accounting and successful replay requests were verified.

The [browser regression runner](verify-readiness.py), also authored before the
implementation, exercises the production expression in Lightpanda against
controlled delayed pages. All four cases pass: completed content with a pending
background request (0.512 s), delayed application content (1.367 s), delayed table
content (1.323 s), and hidden placeholders (0.478 s). The delayed cases wait for
their actual DOM content, not a string in script source. Results are saved in
[readiness checks](results/2026-11-27-quality-final/readiness-checks.json).

This remains a small development-set benchmark with an assistant content audit,
not independent blinded grading or a load test. Page bodies and networks remain
live. The same five-candidate controls do not evaluate larger-pool refill or
optional ranking. Both pipelines still lack Selenium's primary documentation
and the requested KMU comparison in their supplied pools. Both quotation pages
miss the specific world/thinking quotation despite matching broad term signals.
Quelle's long RFC PDF remains explicitly capped at 150 of 194 pages; Firecrawl
rejects that PDF under the unchanged budget. Those existing coverage and budget
limits are separate from the extraction defects fixed here.

Task-owned services and processes were removed after the runs. Existing services
and the remote model service were not restarted. Raw artifacts remain ignored
by Git; source changes, regression checks, runner, query definitions and reports
are versionable.
