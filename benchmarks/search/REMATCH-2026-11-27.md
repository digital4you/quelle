# Quelle vs. SearXNG + Firecrawl after optimization

Quelle is faster overall in this 25-query rematch, but still loses a working
Nuxt documentation page, section-level link destinations, and some table
structure and content cleanup. Rendering validation also remains intermittent
on one Fedlex page. The small speed losses on quotations and Redis did not
persist in the same form on a separate repeat.

This is an assistant audit of saved outputs, not an independently graded quality
score. Keyword coverage and successful-response counts cannot establish an
overall quality winner.

## Controls and scope

The main run completed on November 27, 2026, from 16:24:59 to 16:28:53 CET.
It used the unchanged [25 queries and criteria](queries.json), the same supplied
Brave key, and the optimized release executable. The query SHA-256 is
`b3c48136cc07bb9d7fe62e6dc9b50bdeeae71858231f07d8f9f000474425a751`;
the executable SHA-256 is
`7ae960fbbdd17429409bdda625063f733b007545ca6e5c013e2cb9683590d29c`.
The working tree contains the optimizations; the Git commit alone does not
identify this executable. Exact container identities are in the
[manifest](results/2026-11-27-rematch/manifest.json) and match the original run.

- One live Brave request per query, using CH, explicit language, strict
  SafeSearch, spellcheck off and up to five results. Both adapters received the
  identical response through authenticated local replay. All 25 live requests
  and all 50 paired adapter requests succeeded; the supplied URL sets matched
  SearXNG's selections for all 25 cases. A separate replay smoke check also passed.
- Quelle `/api/content`, engine order, `candidateLimit: 5`, `followUp: false`,
  native Lightpanda, no optional Chromium/OCR sidecars or reranker. The other arm
  used SearXNG `braveapi` and self-hosted Firecrawl `/v2/scrape`, Markdown,
  `onlyMainContent: true`, Playwright available, and no reranker.
- Four concurrent page fetches per pipeline, seeded query order, alternating
  pipeline order, sequential pipelines, fresh services. Firecrawl's scrape
  budget was 25 seconds; Quelle's built-in page-fetch budget is 25 seconds.
  Internal rendering and retry policies remain implementation-specific.
- This holds the original five-candidate comparison constant. It does not
  measure Quelle's larger default candidate pool, refill from extra candidates,
  preferred-domain follow-ups, optional ranking, warm-cache performance, answer
  generation, concurrent load, or Firecrawl's hosted service.

Six live candidate sets changed from the original benchmark: `ch01`, `ch02`,
`tech04`, `tech05`, `date05`, and `hard04`. Compare the two arms within this
rematch; changes from the old report cannot all be attributed to the code.
Only search responses are frozen, not live page bodies or network conditions.
The same queries informed the earlier fixes, so this is a development-set
regression measurement rather than a held-out evaluation.

## Where Quelle still loses quality

### 1. A working Nuxt page is lost through Markdown negotiation

For `tech05`, Quelle reports `not_found` for
`https://nuxt.com/docs/getting-started/data-fetching`. Firecrawl follows it to
the Nuxt 4 article and returns 37,619 characters of substantive documentation.
The same difference recurred in the separate repeat. Other Quelle sources still
match every term signal, hiding the missing current-version article.

A controlled HTTP probe changed only the `Accept` header:

| Accept mode | Final route | Status |
| --- | --- | ---: |
| HTML | `/docs/4.x/getting-started/data-fetching` | 200 |
| Quelle's Markdown-capable header | `/raw/docs/getting-started/data-fetching.md` | 404 |
| Markdown only | `/raw/docs/getting-started/data-fetching.md` | 404 |

This confirms a negotiation/fallback defect, rather than an unavailable original
page. Retry the original URL with HTML-only negotiation when the negotiated
Markdown variant fails, while keeping genuine missing/authentication pages as
failures. Evidence: [paired outputs](results/2026-11-27-rematch/tech05.json),
[header probe](results/2026-11-27-rematch/nuxt-negotiation.json).

### 2. Links lose their section targets

Quelle now emits public link destinations, but strips URL fragments. The official
KMU capital page's legal citation loses `#a773`, and PostgreSQL's numeric-table
reference loses `#DATATYPE-NUMERIC-TABLE`. Firecrawl preserves those destinations.
Readers can reach the document but not the cited provision or table directly.

The link renderer calls the fetch URL normalizer, which removes fragments, and
also skips fragment-only links. Preserve validated fragments in evidence links
separately from fetch/cache normalization. Evidence: [KMU](results/2026-11-27-rematch/ch03.json),
[PostgreSQL table](results/2026-11-27-rematch/hard05.json),
[link renderer](../../src/pages/clean.rs), [URL normalizer](../../src/pages.rs).

### 3. Table structure is less explicit in the tested content output

Quelle now recovers ESTV's old/new VAT dates and all three rate rows; the original
missing-table defect is fixed. Its `/api/content` output still presents labels
and cells as a plain-text sequence. Firecrawl's Markdown table makes the row and
column relationships explicit. The numeric-types table and Swisscom financial
tables show the same structural advantage, even when both preserve the facts.

This is an output-format limitation of the tested endpoint, not a claim that
Quelle has no Markdown support: `/api/scrape` already supports Markdown. A richer
content representation should retain table structure without sacrificing code
whitespace. In the Rust case, Quelle's multiline code is actually better
preserved than Firecrawl's flattened inline-code example. Evidence:
[VAT](results/2026-11-27-rematch/ch01.json),
[numeric types](results/2026-11-27-rematch/hard05.json),
[Swisscom](results/2026-11-27-rematch/date05.json),
[Rust](results/2026-11-27-rematch/tech01.json).

### 4. Main-content cleanup is worse on the SNB release

On the September SNB release, Quelle returns 9,211 characters with 1,146
characters before the main article heading. Firecrawl returns 7,033 characters
with only 96 before that heading. Quelle retains navigation and accessibility
labels that consume context without helping answer the question. Both retain
some cookie-consent text at the end. This is a concrete SNB loss, not a universal
cleanliness advantage: Firecrawl also leaves GitHub sign-in UI in another case.
Evidence: [SNB outputs](results/2026-11-27-rematch/date01.json).

## Remaining weakness that is not a Firecrawl win

The Fedlex historical URL ending `?version=20220213` intermittently passes
Quelle's quality gate with a 4,082-character loading shell: it contains
“Laden der Anwendung” and support/navigation text, but no constitution article
text. Other Quelle sources in that query contain the actual law. In the separate
repeat, the same historical URL returns 296,063 characters of legal text.

Firecrawl returns JavaScript-required notices for all five Fedlex candidates in
both runs. Its faster completion is therefore not faster useful retrieval.
Quelle still needs a stronger rendered-document readiness check; text length
alone is insufficient. Evidence: [main](results/2026-11-27-rematch/hard01.json),
[repeat](results/2026-11-27-rematch-check/hard01.json).

## Where Quelle was slower, and whether it repeated

Four cases were rerun in fresh services using the exact main-run Brave snapshots,
with no new Brave calls. These targeted checks are kept separate from the
25-query aggregate; they were selected after observing the main run.

| Case | Main Quelle / Firecrawl | Repeat Quelle / Firecrawl | Interpretation |
| --- | ---: | ---: | --- |
| JavaScript quotations | 1.955 / 1.453 s | 1.335 / 1.328 s | Initial 0.502 s loss becomes effectively a tie. |
| Redis persistence | 8.029 / 7.515 s | 8.187 / 12.609 s | Quelle stays near 8 s, but the winner reverses. |
| Fedlex constitution | 6.824 / 2.789 s | 7.746 / 2.215 s | Firecrawl is faster at returning unusable notices. |
| Nuxt documentation | 2.756 / 5.163 s | 2.670 / 5.114 s | Quelle stays faster but consistently misses one working page. |

There is no demonstrated consistent Firecrawl speed advantage on useful content
from these repeats. Redis remains a clear Quelle latency hotspot. Its main-run
log records about 7,004 ms rendering the durable-Redis page, near the default
seven-second render wait. Profile readiness-based early completion there; the
log does not prove that every millisecond of that wait is avoidable. The smaller
quotation timing difference needs more repetitions before motivating a specific
performance change. Evidence: [main log](results/2026-11-27-rematch/quelle.log),
[repeat summary](results/2026-11-27-rematch-check/case-summary.json).

another author's quotation, while Einstein appears elsewhere. The broad
predeclared rendering criterion is met, but the exact query's target quotation
is absent. Likewise, matching all terms cannot compensate for missing primary
sources in `cmp03` and `cmp04`, or for the partial PDF in `hard03`. Firecrawl's
RFC PDF error specifically requests at least 34,100 ms for 194 pages; it rejects
the configured budget rather than spending 25 seconds and then timing out.

## Next fixes suggested by this run

1. Add the HTML retry for failed negotiated Markdown, with the Nuxt URL as a
   reproduction case.
2. Preserve section fragments and expose structured tables through the content
   endpoint; retain the current code-whitespace gains.
3. Strengthen rendered-document completion checks, then profile early completion
   on Redis and cleanup on SNB. Faster shell returns must not count as progress.
4. Evaluate document-family/version diversity and missing primary sources in a
   separate larger-pool experiment. A reranker cannot repair failed extraction;
   the existing optional model is not justified as a fix for these losses.

No application fixes or default ranking changes were made during this rematch.
The runner now records supplied candidates, completed-fetch/duplicate diagnostics,
and supports separate snapshot-only repeats. Release compilation, runner syntax,
artifact consistency and diff checks passed. Task-owned benchmark services were
removed after completion; existing services and remote model services were not
restarted.
