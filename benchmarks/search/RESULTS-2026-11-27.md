# Quelle vs SearXNG + Firecrawl: 25-query retrieval benchmark

Quelle was faster on the median query and handled several Swiss JavaScript pages
better. Firecrawl retained some evidence and formatting that Quelle missed.
There is no defensible overall quality winner from HTTP success or keyword
counts alone.

## Run and controls

The completed run is `results/2026-11-27-run3`, from 14:11:43 to 14:16:21 UTC on
2026-11-27. Quelle commit: `efbad0f5c9c5611335ea4e55a368a34f87120411`.
The release binary was rebuilt before running. SearXNG image revision:
`b5605b8f2`; Firecrawl build: `cb8e1c09106eaa600dafad67806fbde5e0a708a8`.
Exact image identities and binary hash are in the [manifest](results/2026-11-27-run3/manifest.json).

The [25 query definitions](queries.json) and their evidence requirements were
fixed before running: five each for Swiss research, technical docs, dated facts,
comparisons and difficult pages. The fixture hash remained unchanged.

Each query used one live Brave request with the user-supplied key. Both pipelines
received its identical saved response, using CH, explicit language, strict
SafeSearch, spellcheck off and up to five results. This controls for differing
adapter defaults and search drift. The production upstream request was made by
the harness; pipeline adapters used temporary replay credentials, not a second
Brave account. All 25 upstream requests succeeded. All 50 adapter replay requests
succeeded, and the attempted URL sets matched for all 25 pairs.

Quelle used `/api/content` with native Lightpanda, without the optional Chromium
or OCR sidecars. The comparison used SearXNG's `braveapi` engine followed by
self-hosted Firecrawl `/v2/scrape`, with its Playwright service configured.
Each pipeline allowed four concurrent page requests. Query order was seeded,
pipeline order alternated, and pipelines ran sequentially. No answer generation,
query expansion or learned reranker was used. This does not measure Firecrawl's
hosted service or Quelle's `/api/answer` endpoint.

Two setup attempts were excluded: one found that this self-hosted Firecrawl build
rejects `maxAge`; another found that SearXNG needed HTTP enabled for the local
replay endpoint. The final run passed both service smoke checks before collecting
data. All task-owned processes, containers and volumes were removed afterward.

## Measurements

| Metric | Quelle | SearXNG + Firecrawl |
| --- | ---: | ---: |
| Queries returning some text | 25/25 | 25/25 |
| Attempted URLs | 114 | 114 |
| Nonempty outputs reported as successful | 112 | 112 |
| Explicit pipeline errors | 2 | 2 |
| Median retrieval time, excluding live search | 1.71 s | 3.35 s |
| p95 retrieval time, nearest-rank | 7.60 s | 12.75 s |
| Median paired search + retrieval estimate | 2.53 s | 4.30 s |
| Queries matching every predeclared term signal | 25/25 | 24/25 |

The shared live Brave request had a median of 0.95 seconds. The combined estimate
adds each query's actual Brave latency to its replay-backed retrieval latency;
it is not the sum of the two aggregate medians. These are single observations
per query, not a load test or repeated latency study.

**Nonempty output is not necessarily useful evidence.** Both pipelines returned
404/401 page text as successful output. The term signals can match navigation,
unrelated passages or old versions and do not establish factual correctness.
The raw `official_sources` field is only a predeclared host-allowlist match,
not a reliable authority score: it misses legitimate sources such as BAK and
cantonal sites, and is affected by different redirect metadata. It is deliberately
excluded from the headline comparison.

## Evidence audit

These observations come from assistant inspection of the saved outputs. They are
not independent blinded judgments or a completed relevance-grade dataset.

| Case | Observation |

| ch02 — Zefix/UID | Both retrieve explanatory register pages. Quelle renders the Zefix interface; Firecrawl includes unsupported-browser notices. Firecrawl preserves useful destination links that Quelle's plain text drops. |
| ch03 — GmbH capital | Both include official SME guidance covering capital and full payment. |
| ch04 — Swiss languages, French | Both retrieve BAK's Article 4 explanation. Both also return a university 404 page; Quelle corrupts accented text on another legacy page. |

| tech04 — HTTP 429 | Both retain the status and Retry-After explanations. Redirect aliases duplicate evidence, and one result is Russian despite an English query. |
| tech05 — Nuxt hydration | Both retain the payload-transfer explanation and code. Quelle retrieves raw Markdown alternatives. |
| date01 — September 2026 SNB | Both contain the dated decision and policy rate. Firecrawl removes more navigation on these pages. |
| date02 — October 2026 CPI | Both contain the current official release listing. Quelle also renders the calculator; Firecrawl returns its logo/language shell. Old BFS URLs redirect and duplicate content. |
| date03 — Rust 1.90 release | Both include the actual release announcement, date and changes, alongside broad indexes and advance announcements. |
| date04 — PostgreSQL 18 release | Both include the actual announcement and release notes. A release-candidate page also occupies a slot. |
| date05 — Swisscom 2025 results | Both include annual-results material; quarterly reports also occupy slots. Units and periods still require careful reading. |
| cmp01 — SQLite WAL | Both retrieve SQLite's primary explanations. Both time out/fail on one mirror and count an unauthorized mirror page as successful text. |
| cmp02 — Parquet/CSV | Both retrieve substantive comparisons and Apache's GitHub specification. Quelle times out on one other result; Firecrawl counts that site's 503 error page as success. |
| cmp03 — Playwright/Selenium | Both retrieve Playwright's own auto-waiting docs and third-party comparisons. Neither retrieves Selenium's own docs: the fixed primary-evidence criterion is only partly met despite all term signals matching. |
| cmp04 — Einzelfirma/GmbH | Both retrieve comparisons, but neither retrieves the requested official SME guidance. Both also return a deployment-not-found page as successful text. |
| cmp05 — Redis persistence | Both retain primary RDB/AOF explanations. On the separate durable-Redis page, Quelle returns navigation/footer text while Firecrawl retrieves the article. |
| hard01 — Fedlex constitution | Quelle retrieves legal text. All five Firecrawl outputs are JavaScript-required notices, with none of the three evidence signals. |
| hard02 — Transformer paper PDF | Both retrieve substantive paper text. Two host variants duplicate the same paper. This tests a text-layer PDF, not OCR. |
| hard03 — Long HTTP RFC | Both retrieve substantive HTML/XML. Quelle's PDF is explicitly truncated at 150 of 194 pages. Firecrawl rejects that PDF under the 25-second timeout and asks for a longer budget. Neither achieved complete PDF retrieval. |
| hard04 — JavaScript quotations | Both retrieve actual quotations and attribution. |
| hard05 — Numeric types table | Both retain type/size/range associations. Quelle returns readable rows; Firecrawl returns a Markdown table. The VAT-table omission does not generalize to every table. |

The apparent 25/25 versus 24/25 signal advantage is therefore **not an accuracy
score**. Missing primary sources in `cmp03` and `cmp04` affect both systems,
while several extraction defects occur on individual pages even when another
page satisfies the query.

## Reranking decision

Keep this result as the baseline. Then run a separate experiment with 20 candidates
per query and the same reranker selecting five for each pipeline. Freeze the
candidate responses and hold model, prompt, language and fetch budget constant.
Use graded relevance/evidence coverage and added latency to decide whether it helps.

Quelle's content endpoint currently preserves engine order. Its answer endpoint
already uses the configured chat model (`QUELLE_MODEL_NAME`) to rerank up to 40
candidates by titles/snippets, with a fallback to the prior order. There is no
dedicated cross-encoder here. The SearXNG + Firecrawl composition tested here has
no learned reranker; SearXNG can still reorder results through its ordinary ranking.

Before adding a model, the observed engineering priorities are recognizing
error pages and incomplete rendering, preserving evidence-bearing content,
and deduplicating redirects and document versions. Reranking cannot restore text
an extractor never returned or select a source absent from the candidate pool.
